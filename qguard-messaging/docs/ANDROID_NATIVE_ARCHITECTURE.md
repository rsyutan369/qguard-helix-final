# QGuard Messaging — Android Native Architecture

## Overview

The Android build of QGuard Messaging is produced from the same codebase as the
desktop app via **Tauri 2 mobile**. Every security-critical cryptographic
operation executes in **native ARM64 machine code compiled with Android NDK
r27** — none of the cryptography runs in JVM-managed code.

```
WebView UI (React + Tailwind, mobile shell)
        │  tauri://invoke (typed commands)
Kotlin activity layer (TauriActivity / MainActivity)
        │  JNI  (generated by Tauri; libqguard_messaging_lib.so)
──────────────────────────────────────────────────────
Native layer — Rust, built with NDK r27 clang/LLVM
──────────────────────────────────────────────────────
 crypto/         hybrid_kex (X25519 + ML-KEM), signatures (Ed25519 + ML-DSA),
                 symmetric (AES-256-GCM), kdf (HKDF-SHA3-256), PQClean C cores
 messaging/      double-ratchet sessions, sealed envelopes, replay protection
 vault/          Quantum Vault streaming encryption engine (ML-KEM-1024 profile)
 security/       keystore.rs (Android Keystore JNI), obfuscation, hardening
 state.rs        identity + prekey lifecycle, encrypted key-material store
        │
Android Keystore (hardware-backed DEK wrapping key, TEE/StrongBox)
Android 10+ ARM64 device (also armv7 / x86_64 emulator ABIs)
```

## Why the native layer is Rust (not a parallel liboqs build)

The QGuard Helix engineering constitution forbids duplicate crypto services.
The desktop-proven Rust core already implements the approved stack, and the
`pqcrypto` crates wrap **PQClean's C reference implementations** — the same
implementations liboqs itself packages for ML-KEM and ML-DSA. Compiling that
C + Rust core with the NDK yields the exact "native cryptography via NDK r27"
outcome with zero duplicated, unaudited code. The `oqs-backend` cargo feature
remains reserved for a liboqs backend as a crypto-agility option.

| Requirement (Android_Building_2)   | Fulfilled by |
|------------------------------------|--------------|
| NDK r27 + LLVM/Clang               | `ndk;27.2.12479018`, cargo cross-compile for 4 Android ABIs |
| Native ML-KEM / ML-DSA             | PQClean C cores (pqcrypto-kyber / pqcrypto-mldsa) compiled by NDK clang |
| JNI bridge, minimal exposure       | Tauri's generated Kotlin↔Rust JNI + `security/keystore.rs` (Android Keystore); no key material crosses into Kotlin |
| Android Keystore                   | Hardware-backed AES-256-GCM wrapping key; see `security/keystore.rs` |
| Secure memory                      | `zeroize` on all secret buffers; keys never logged |
| WebRTC native                      | Android System WebView's libwebrtc (native C++), with QGuard PQC frame crypto on top |
| Secure RNG                         | `getrandom` → `/dev/urandom` (kernel CSPRNG, hardware-seeded) |

## Module boundaries

- The native layer is UI-agnostic: commands in `src-tauri/src/commands/` are
  the only entry points, invoked over Tauri's JNI-backed IPC.
- Kotlin (`gen/android/app/src/main/java/`) contains **no cryptography** —
  only activity lifecycle, runtime permissions, and WebView hosting.
- The WebView renders UI and runs WebRTC media; media-frame encryption keys
  are derived natively and injected per-call (see WEBRTC_SECURITY.md).

## Platform divergence points (desktop vs Android)

| Concern            | Desktop                          | Android |
|--------------------|----------------------------------|---------|
| DEK storage        | OS keychain (`keyring` crate)    | Android Keystore-wrapped file (JNI) |
| Data dir           | `%APPDATA%/qguard-messaging`     | `app_data_dir()` (sandboxed, FBE-encrypted) |
| Updates            | tauri-plugin-updater (minisign)  | Signed APK / Play distribution |
| Process/relaunch   | tauri-plugin-process             | Not registered (Android lifecycle) |
| Capabilities       | `default.json` + `desktop.json`  | `default.json` only |
