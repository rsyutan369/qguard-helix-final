# QGuard Messaging security claims audit — 2026-11-15 to 2026-11-16

Scope: `/qguard-messaging`, `/qguard-messaging/secure-chat`, and `/qguard-messaging/quantum-vault`; Windows and Android Messaging source (1.5.3), the repository’s Windows installer (1.5.0), and the Helix integrations described by these pages. This is a source and claims audit, not an independent protocol review, FIPS validation, production configuration review, or release-binary attestation. Page illustrations contain example data.

## Corrections and remaining checks

- Removed claims of one uniform protection stack, blanket quantum safety, universal ML-KEM use on every message and file, and release parity. Replaced the unsupported competitor scorecard with the first-party workflow matrix above. The Windows file’s product version and SHA-256 matched the page metadata; Android distribution availability was not established by finding packaged artifacts.
- Corrected Hidden Vault recovery, backup/sharing metadata, call phrase scope, optional ratchet behavior, and guarantees about streaming and deletion. Messaging CTAs now lead to the gated Windows download. Helix account sign-in is labeled separately.
- The download plan chooser had stale monthly prices and used a yearly billing parameter that checkout interpreted as monthly. The chooser now uses checkout’s pricing source and billing parameter. Backup quotas are labeled in GiB to match the byte values in migration 048.
- Collector previously inferred X25519 for suites that omitted the classical key exchange, and treated published configuration as high-confidence evidence. It now records only reported components and uses medium confidence. Existing stored evidence was not reprocessed as part of this review.
- [FIPS 203](https://csrc.nist.gov/pubs/fips/203/final) is the ML-KEM standard for key establishment. [FIPS 204](https://csrc.nist.gov/pubs/fips/204/final) and [FIPS 205](https://csrc.nist.gov/pubs/fips/205/final) standardize distinct signature schemes. [NIST CMVP](https://csrc.nist.gov/projects/cryptographic-module-validation-program) validates specific modules and environments; using standardized primitives or enabling a restricted build mode does not establish that validation. See the [Messaging module status](../qguard-messaging/docs/FIPS_140_3.md).
- Before treating the reviewed source as release evidence, verify signed Android and Windows builds on real paired devices. Cover direct and group messaging; encrypted audio/video negotiation; modified/truncated Vault files; cloud backup and restore permissions; Hidden Vault recovery from retained files; and Android↔Windows Mesh/XFER over supported links. Verify deployed relay/database migrations and Helix import with dedicated test accounts. No authenticated production operation was performed for this audit.

## Verification performed

- Rendered each public page and the download plan chooser from the real React components and checked the workflow copy, build labels, pricing and download navigation markup. Browser automation could not complete on this host: headless Chrome timed out and sandboxed connections to localhost were denied.
- The Messaging frontend suite passed all 771 tests using `NODE_OPTIONS=--no-experimental-webstorage` to keep Node’s built-in storage from overriding the test WebView storage. The Helix Messaging posture check passed all 18 cases.
- `aapt2` identified the local APK as `com.qguard.messaging` v1.5.3 for `arm64-v8a`. `apksigner` verified its v2 signature. The APK and AAB matched the local SHA-256 manifest. This does not establish Play Store availability, build provenance or feature parity. The repository Windows installer’s product version is 1.5.0 and its SHA-256 matched the Windows download panel. Its update manifest’s Ed25519 signature also verified against the installer and the updater public key in the app configuration.
- The native Rust suite did not run: the host’s Windows GNU toolchain could not compile `pqcrypto-mlkem` because its bundled PQClean compatibility header expected `features.h`. No native test pass is claimed.
