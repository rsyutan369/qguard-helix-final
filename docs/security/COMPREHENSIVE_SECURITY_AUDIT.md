# Qguard Helix security audit

17 November 2026 · `feature/qguard-offline-mesh-xfer-vault` · base `918c658` with pre-existing working-tree changes

## Executive summary

The source review produced seven fixes, with three high and four medium review priorities. Git history also contains a complete legacy Supabase `service_role` JWT whose current validity is unknown. Treat its retirement as the highest-priority open action. The platform and Messaging web builds passed. Hosted tenant isolation, release binaries, and all remaining issues require further verification before production security sign-off.

The platform comprises a Vite/React SPA and public site, Express API processes, Supabase Auth/PostgREST/Postgres/Realtime and Edge Functions, an endpoint agent, and a separate React/Tauri Messaging application with Rust and Android code. Browser and agent ingress crosses Cloudflare, a gateway or reverse proxy, and Express. The API uses user-scoped Supabase clients for many tenant operations and a service client for selected operations that require explicit ownership checks. Scanner requests, provider webhooks, and cloud SDK operations create additional boundaries. The inventory also includes media projects, generated reports, and checked-in third-party research and tooling under `output/`. Their presence in Git does not establish runtime reachability.

## Verification boundary

No deployment or production database migration was performed. The Cloudflare workflow informed reconnaissance, independent source review, and evidence triage. The complete Cloudflare execution and record-verification workflow was not completed. The checklist in `Qguard_Wiki/Security_Audit_Latest` remains open for full route and feature coverage, native release verification, hosted configuration, and staging two-account tests. Treat the source changes as candidates for staged verification. A clean result from an individual scanner is limited to its input, configuration, and advisory database.
